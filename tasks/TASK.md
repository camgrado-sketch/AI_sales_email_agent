# 项目任务拆解 (TASK.md)

本项目分为四个核心阶段进行开发。每个阶段需独立完成并进行黑盒测试。

## 阶段一：基础架构重构与 CLI 交互界面
**目标**：搭建交互式控制台，集成 LLM API 基础调用。

| 任务 ID | 任务描述 | 验收标准 |
| :--- | :--- | :--- |
| TASK-1.1 | 创建 `docs/`, `tasks/`, `templates/`, `assets/` 等标准目录结构。 | 目录结构完整，配置文件就绪。 |
| TASK-1.2 | 开发 `cli_controller.py`，实现终端菜单交互。 | 终端可显示菜单，能接收用户输入并流转到不同功能模块。 |
| TASK-1.3 | 集成 LLM API 客户端。在 `.env` 中配置密钥，编写基础调用函数。 | 脚本能成功调用 LLM API 并返回测试文本。 |

## 阶段二：模板引擎与富媒体支持
**目标**：实现 HTML 邮件的动态生成与图片嵌入。

| 任务 ID | 任务描述 | 验收标准 |
| :--- | :--- | :--- |
| TASK-2.1 | 编写 `template_engine.py`，解析 YAML 规则和 HTML 模板。 | 能够读取 `templates/` 目录下的配置文件。 |
| TASK-2.2 | 实现占位符替换逻辑（将 `{{IMAGE:xxx}}` 替换为内联图片或 CID）。 | 生成的 HTML 源码中正确包含 `assets/` 目录下的图片数据。 |
| TASK-2.3 | 将原有纯文本邮件生成逻辑重构为调用模板引擎生成 HTML。 | 能够输出包含格式和图片的 `drafts.json` 文件。 |

## 阶段三：智能分析与闭环生成
**目标**：实现 CRM 数据读取、历史互动分析和自动草稿生成。

| 任务 ID | 任务描述 | 验收标准 |
| :--- | :--- | :--- |
| TASK-3.1 | 开发 `interaction_analyzer.py`，读取日志评估客户状态。 | 能根据历史日志输出客户当前的销售阶段（如“已联系未回复”）。 |
| TASK-3.2 | 开发 `email_generator.py`，串联 CRM 数据、状态分析和模板引擎。 | 运行后，能为 CSV 中的客户自动生成对应的个性化邮件草稿。 |
| TASK-3.3 | 在 CLI 中实现“逐条审核”功能。 | 用户能在终端预览草稿，按 Y 标记为通过，按 N 拒绝。 |

## 阶段四：送达率优化与发送队列
**目标**：实现安全的发送策略，防止被判定为垃圾邮件。

| 任务 ID | 任务描述 | 验收标准 |
| :--- | :--- | :--- |
| TASK-4.1 | 开发 `deliverability.py`，实现频率控制和随机延迟逻辑。 | 连续发送多封邮件时，时间间隔符合设定的随机区间。 |
| TASK-4.2 | 集成基础的 DNS (SPF) 检查功能。 | 发送前能验证发件域名的基础配置，配置错误时给出警告。 |
| TASK-4.3 | 重构 `sender.py`，支持 HTML 格式和附件/内联图片的发送。 | 真实邮箱能收到排版正确的带图 HTML 邮件。 |
