## 2. 第二次人工测试：带图邮件发送失败分析

**现象**：发送已审核邮件时，系统提示图片文件缺失（如 `开发信2_img_01`），询问是否继续。

### 2.1 根因分析
经过对 `template_importer.py` 和 `email_generator.py` 的逻辑追溯，定位到图片缺失的**核心逻辑漏洞**：

1.  **图片清理机制过严**：`template_importer.py` 中的 `_cleanup_template_images` 会在**每次重新导入模板**时，立即删除 `assets/images/` 下所有属于该模板旧版本的图片。
2.  **草稿与资源脱钩**：生成的草稿（`drafts.json`）仅记录了图片的本地路径。如果您在**生成草稿后、正式发送前**，由于某种原因重新导入了同名模板（例如为了微调文字），系统会把旧草稿引用的图片文件删掉。
3.  **结果**：当您执行发送时，系统检查 `drafts.json` 里的路径，发现文件已不存在，从而触发警告。

### 2.2 解决方案建议
- **短期绕过**：生成草稿并审核通过后，在发送完成前，**禁止重新导入同名模板**。
- **长期修复**：
    - **A 方案（资源持久化）**：导入模板时，将图片存入带时间戳或版本号的文件夹。
    - **B 方案（导入拦截）**：若检测到当前模板仍有待发送的草稿，禁止重新导入（PR #12 已初步实现此拦截，但仍需加固）。
