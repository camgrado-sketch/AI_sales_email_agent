# 用户操作流程 (UserFlow.md)

本文档描述系统在终端控制台（Interactive CLI）中的标准使用流程，分为**首次配置**和**日常使用**两个场景。

---

## 场景一：首次配置（仅需执行一次）

### Step 1 — 配置发送者身份
```
主菜单 → [S] 设置 → [1] 发送者信息
```
按提示逐项输入姓名、职位、公司、负责区域、联系电话。信息保存至 `templates/sender_profile.md`，后续所有邮件签名自动引用。

### Step 2 — 配置 LLM 与邮箱
在 `.env` 文件中填写 LLM API Key、邮箱账号和授权码。此步骤仅需一次，详见 `docs/CONFIG_GUIDE.md`。

---

## 场景二：导入新模板（低频，模板更新时执行）

### Step 1 — 放置模板文件
将 `.md`、`.docx` 或 `.pdf` 格式的邮件模板放入 `templates/import/` 目录。若模板中包含图片，系统会自动提取并保存至 `assets/images/`，无需手动操作。

### Step 2 — 执行导入
```
主菜单 → [6] 导入/确认模板 → [I] 导入新文件
```
终端显示检测到的新文件列表，输入编号选择。系统在后台调用 LLM 解析，完成后打印解析结果（变量列表、图片列表、生成的邮件标题）。

### Step 3 — 选择生效模板
```
模板管理菜单 → [A] 选择生效模板
```
终端列出所有已激活的模板及其状态，输入编号选择。选择后长期生效，直到下次手动更改。

### Step 4 — 预览并确认
```
模板管理菜单 → [C] 确认/重置
```
系统自动弹出浏览器窗口（或生成截图）展示模板效果，变量占位符高亮显示。在终端输入 `Y` 确认，模板进入"已确认"状态，可用于生成邮件。

---

## 场景三：日常发邮件（高频，每次发送前执行）

### Step 1 — 检查状态栏
每次启动后，终端顶部显示当前状态：
```
─────────────────────────────────────────────────────
模板: initial_contact (2026-08-01) ✅已确认
发送: 未发送  |  回复: 0 封
─────────────────────────────────────────────────────
```
若模板未确认，状态栏会警告并阻止生成操作。

### Step 2 — 生成邮件草稿
```
主菜单 → [1] 生成
```
系统读取 `data/customers.csv`，自动判断每个客户的语言（中/英），将客户信息和发送者信息注入当前生效模板，本地替换变量，生成草稿。终端显示进度，完成后提示"已生成 N 封草稿"。

### Step 3 — 逐条预览审核
```
主菜单 → [2] 审核
```
系统逐条弹出草稿预览（含真实图片和数据），终端提示：
```
客户: John Smith <john@gensler.com>
模板: initial_contact | 语言: en
主题: Introducing GRADO Contract for Your Projects
[Y] 通过  [N] 拒绝  [S] 跳过  [E] 编辑  [Q] 退出审核
```

### Step 4 — 发送
```
主菜单 → [3] 发送
```
系统读取所有"已通过"草稿，按频率控制策略（随机间隔 30-120 秒）依次发送。发送结果记录至 `data/email_logs.csv`，状态栏实时更新。

### Step 5 — 查看回复
```
主菜单 → [4] 回复
```
系统连接 IMAP 检查收件箱，匹配已发邮件的回复，弹出回复预览，可选择保存至 `data/reply_logs.csv`。

---

## 状态流转图

```
客户数据 (customers.csv)
        │
        ▼
[1] 生成草稿 ──────────────────────────► drafts.json (status: pending)
                                                │
                                                ▼
                                        [2] 逐条审核
                                         ├─ Y → status: approved
                                         └─ N → status: rejected
                                                │
                                                ▼
                                        [3] 发送队列
                                         ├─ 成功 → email_logs.csv (delivered)
                                         └─ 失败 → email_logs.csv (failed)
                                                │
                                                ▼
                                        [4] 回复采集
                                         └─ reply_logs.csv
```
